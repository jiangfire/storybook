# Storybook 系统概述

> 项目代号：storybook | 模块：`github.com/jiangfire/storybook` | Go 版本：1.25.4

## 一、项目定位

Storybook 是一个围绕用户故事（User Story）的敏捷协作系统，覆盖产品、开发、测试、技术负责人、管理员五类角色。当前仓库已经不止于 MVP，而是包含项目管理、故事审批、任务拆分、测试用例、缺陷、报表、全局搜索、MCP 接口与嵌入式前端。

核心流程如下：

1. 产品经理在项目下创建故事，初始状态为 `pending`，等待审批。
2. 技术负责人或管理员审批故事；通过后进入 `backlog`，驳回则保留审批意见。
3. 产品经理、技术负责人或管理员可将故事分配给项目内开发成员。
4. 开发、测试围绕故事继续推进任务、测试用例、缺陷与状态流转。

## 二、当前技术架构

### 2.1 后端

- 框架：Gin
- 数据访问：GORM
- 数据库：SQLite（默认）/ PostgreSQL（可选）
- 认证：JWT Access Token + Refresh Token
- 实时能力：gorilla/websocket
- 配置方式：环境变量统一收口在 `internal/config.Config`，包含 JWT、数据库、向量后端、AI 限流等全部运行时参数
- 装配方式：`internal/wiring.Build` 把 cfg/db/logger/tokenManager/hub/notifier/vector 与 17 个 handler 装入 `Container`，由 `router.New(container)` 注册路由
- 接口组织：`handler -> service -> repository/model`；Top5 高 fan-in 仓储（Story / Project / Task / User / ActivityLog）已抽出 `Repo` 接口于 `internal/repository/interfaces.go`，handler 字段持接口而非 concrete struct
- AI 接口：`service.AIService` 聚合 `StoryGenerator`（故事生成/流式/批量/Refine）与 `ChatCompleter`（自由对话），openAI 与启发式实现同时满足两面

### 2.2 前端

- React 19 + TypeScript
- 路由：`react-router-dom` 7.x
- 状态管理：Zustand
- 构建工具：Rsbuild
- 样式：Tailwind CSS 4
- 测试：Vitest + Testing Library

当前前端界面原则：

- 顶部导航只承担应用壳层职责，不作为主导航
- 左侧侧栏是桌面端主导航；移动端收敛为顶部导航条
- 页面风格以实体卡片、清晰边界、克制留白为主
- 已明确放弃玻璃拟态、悬浮遮挡和高噪音动效方向
- 项目列表、项目详情、缺陷管理、个人工作台已完成同一套工作台语言收口

### 2.3 前后端集成

前端源码位于 `storybook-page/`。生产构建后可同步到 `internal/webui/dist`，由后端通过 `embed` 提供静态资源与 SPA 回退路由。仓库同时保留：

- `pnpm run build:embed`：前端侧直接复制构建产物
- `go run ./cmd/embedui`：后端侧同步构建产物

## 三、当前能力边界

仓库已实现的主干能力包括：

- 用户注册、登录、刷新令牌、登录失败锁定
- 项目 CRUD、成员管理、技术负责人管理、概览统计
- 用户故事 CRUD、看板、审批、分配、归档、活动历史、代码引用
- 子任务、测试用例、冲刺、缺陷管理
- 速度、质量、燃尽报表
- 全局搜索、个人工作台、WebSocket 推送
- MCP HTTP 接口：故事 AC、覆盖率、状态更新、生成 AC 测试模板、代码与 AC 分析
- 用户管理接口：列表、创建、更新、工作负载、删除

## 四、目录结构

```text
storybook/
├── cmd/
│   ├── server/        # 主 HTTP 服务
│   └── embedui/       # 同步前端产物到嵌入目录
├── internal/
│   ├── api/           # 统一响应封装
│   ├── auth/          # JWT 与鉴权
│   ├── bootstrap/     # 首个管理员引导
│   ├── config/        # 环境变量配置（单一来源）
│   ├── database/      # 数据库连接与 AutoMigrate
│   ├── e2e/           # 端到端测试
│   ├── handler/       # HTTP 处理器
│   ├── logging/       # 结构化日志
│   ├── middleware/    # 认证、限流、CORS、项目/故事访问控制
│   ├── model/         # GORM 模型与常量
│   ├── realtime/      # WebSocket Hub
│   ├── repository/    # GORM 仓储；Top5 含 Repo 接口
│   ├── router/        # 路由注册（消费 wiring.Container）
│   ├── service/       # 领域服务（AIService、Notifier、Vector 等）
│   ├── util/          # 通用工具（日期解析等）
│   ├── webui/         # embed 前端静态资源
│   └── wiring/        # cfg → handler/service 装配容器
├── pkg/mcp/           # 可复用 MCP 服务实现（由 server 进程承载）
├── storybook-page/    # React 前端
├── docs/              # 设计与接口文档
└── scripts/           # 辅助脚本
```

## 五、运行与配置

默认配置来自环境变量，全部在 `internal/config/Config` 中读取后由 `wiring.Build` 分发：

- `SERVER_ADDR`：默认 `:8080`
- `DB_DRIVER`：默认 `sqlite`
- `DB_DSN`：默认 `storybook.db`
- `JWT_SECRET`：生产环境必须覆盖
- `AI_USER_RATE_LIMIT_PER_MIN`：默认 10，每用户每分钟 AI 调用上限
- `EMBEDDING_PROVIDER` / `OPENAI_API_KEY` / `OLLAMA_URL` / `OLLAMA_MODEL` / `OLLAMA_DIMENSION`：向量检索后端可选配置，未设置则跳过 VectorService 初始化

数据库初始化由应用启动时的 `AutoMigrate` 完成，文档中的 SQL、触发器和备份策略应视为设计建议，不代表当前仓库已经全部落地。
