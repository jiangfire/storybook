# Storybook 系统概述

> 项目代号：storybook | 模块：git.neolidy.top/neo/storybook | Go版本：1.25.4

## 一、项目背景

### 1.1 问题陈述
当前需要构建一个支持产品-开发-测试三角色协同的工单系统，核心围绕用户故事进行需求管理和迭代开发，遵循敏捷开发原则。系统名称为"Storybook"，寓意：故事之书，记录每一个用户故事的完整生命周期。

### 1.2 核心目标
- 以用户故事为中心的需求管理
- 支持Scrum（冲刺）和Kanban（看板）双模式
- 产品-开发-测试角色协同工作流
- 可视化进度跟踪和状态流转
- **AI辅助需求拆解与AC验证**（核心创新）

### 1.3 目标用户

| 角色 | 职责 | 核心诉求 |
|------|------|----------|
| **产品经理** | 需求管理、优先级排序、验收 | 快速录入需求，可视化需求状态，验收方便 |
| **开发人员** | 任务领取、开发实现、代码关联 | 清晰知道要做什么，方便关联代码提交 |
| **测试人员** | 测试用例、缺陷跟踪、质量把控 | 测试用例可追溯，缺陷流程清晰 |
| **项目经理** | 进度跟踪、团队协作、数据统计 | 燃尽图、速率、团队负载一目了然 |

## 二、技术架构

### 2.1 技术栈

**后端**：
```
- 框架：Gin（轻量高性能）
- 数据库：PostgreSQL + GORM
- 认证：JWT
- 配置：Viper
- 日志：logrus / zap
- WebSocket：gorilla/websocket
```

**前端**：
```
- React 19 + TypeScript
- Zustand（状态管理）
- Tailwind CSS 4
- Rsbuild
- @dnd-kit（拖拽）
- react-router v6
```

**部署**：
```
- 单体部署（推荐）：前端构建产物 embed 到 Go server 二进制
- 分离部署（可选）：前端静态站点 + 后端 API 服务
```

### 2.3 核心创新：AC驱动开发

传统开发流程的问题：
1. 需求文档和代码实现脱节
2. AC（验收标准）只在测试阶段才被检查
3. 开发过程中容易遗漏细节
4. Code Review时难以对照AC逐项检查

**Storybook的解决方案**：
- **AC即代码**：每个AC都有对应的测试和验证逻辑
- **MCP集成**：Claude Code在开发过程中实时检查AC覆盖度
- **可视化追踪**：清晰显示每个AC的实现状态（未开始/开发中/已完成）

```
│                    AC驱动开发流程                             │

│           │                                                   │
│           ▼                                                   │
│  3. 开发人员实现功能，MCP实时验证AC覆盖度                       │
│           │                                                   │

│  4. 提交前MCP自动检查：所有AC是否通过                          │
│           │                                                   │
│           ▼                                                   │
│  5. 代码审查时对照AC清单逐项确认                               │
└──────────────────────────────────────────────────────────────┘
```

## 三、开发范围规划

### 3.1 MVP阶段（Must Have）

**核心功能**：
- 用户认证与权限（3个用户故事）
- 项目管理基础（2个用户故事）
- 用户故事CRUD（3个用户故事）
- 看板视图与拖拽（2个用户故事）
- 故事详情与活动历史（2个用户故事）
- 项目统计（1个用户故事）

**MCP服务基础功能**：
- 读取用户故事和AC
- AC覆盖度检查
- 生成AC验证模板

### 3.2 第二阶段（Should Have）

- 项目成员管理
- 故事删除和归档
- 高级筛选和搜索
- 个人工作台

**MCP服务增强**：
- 代码到AC的映射分析
- 自动生成测试用例
- AC实现度报告

### 3.3 第三阶段（Could Have）

**AI辅助创新**：
- AI生成用户故事和AC
- AI拆分大故事
- AI检查故事质量（INVEST原则）

**MCP服务AI增强**：
- 智能AC建议
- 需求完整性检查
- 风险点识别
