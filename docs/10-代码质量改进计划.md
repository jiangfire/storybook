- **文件**: `internal/repository/base.go:43-49`

- **动作**:
  1. 先 `grep -rn "\.Count(" internal/repository/` + `grep -rn "Repository\.Count\|repo\.Count(" internal/` 列出实际调用点。

  3. 若有调用点,改实现为 `r.db.Model(new(T)).Where(conds[0], conds[1:]...).Count(&count)`(GORM 风格),并补一个单测验证 conds=nil 与 conds=过滤两种语义。
- **验收**: 方法被删除,或行为正确并有覆盖测试;`go test ./internal/repository/...` 全绿。

- **现状**: `wiring.Build` 内每个 handler 仍是 `handler.NewXxxHandler(db)`,handler 构造函数内部自己 `NewXxxRepository(db)`。
- **拟动作**: wiring 先构造一组 repo(接口实现),再注入到 handler;handler 不再持有 db。
- **优先级**: 低。当前测试用 sqlite + 同一 db 实例,不强求 mock。等到真正补 handler 单测时再做。

- **不接口化 TestCase/BoardColumn/Notification repo**: 单 handler 调用面,接口化净收益 < 0。
- **不在 P2.1 之前做 P3.1 第二轮**: 鉴权中间件铺开之后,handler 真正能瘦身;反过来则改两遍。
