# 用户故事拆解

> 本文档将系统功能按Epic组织，每个用户故事包含标准格式和详细的验收标准（AC）。
> 所有AC将作为开发、测试、代码审查的依据，并通过MCP服务进行自动化验证。

---

## Epic 1: 用户认证与权限管理

### US-1.1: 用户注册

**用户故事**：
> 作为 新用户，
> 我想要 注册账号，
> 以便 我能够使用Storybook系统进行项目管理。

**验收标准（AC）**：

| AC ID | 描述 | 优先级 | 验证方法 |
|-------|------|--------|----------|
| AC-1.1.1 | 可以通过邮箱和密码注册 | P0 | 功能测试 |
| AC-1.1.2 | 邮箱格式验证（符合RFC 5322） | P0 | 功能测试 |
| AC-1.1.3 | 密码强度要求：至少8位，包含字母和数字 | P0 | 功能测试 |
| AC-1.1.4 | 注册时需要选择角色（产品/开发/测试） | P0 | 功能测试 |
| AC-1.1.5 | 注册成功后自动登录并返回JWT Token | P0 | 接口测试 |
| AC-1.1.6 | JWT Token有效期24小时 | P0 | 接口测试 |
| AC-1.1.7 | 邮箱不能重复注册，返回明确错误提示 | P0 | 功能测试 |
| AC-1.1.8 | 密码使用bcrypt加密，salt rounds >= 10 | P1 | 安全测试 |
| AC-1.1.9 | 注册接口限流：同IP每分钟最多3次 | P1 | 安全测试 |

**技术实现要点**：
```go
// 注册请求结构
type RegisterRequest struct {
    Email    string `json:"email" validate:"required,email"`
    Password string `json:"password" validate:"required,min=8"`
    Role     string `json:"role" validate:"required,oneof=product developer tester"`
}

// 密码验证正则
var passwordRegex = regexp.MustCompile(`^(?=.*[A-Za-z])(?=.*\d).{8,}$`)
```
