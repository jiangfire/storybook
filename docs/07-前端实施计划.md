# Storybook 前端开发实施计划

## 📋 项目概述

开发 Storybook 系统的前端界面，一个支持敏捷项目管理的 Web 应用。

### 当前实现对照

已落地：
- 登录/注册、路由守卫、主布局、Toast、Skeleton
- 项目列表、项目详情、看板拖拽、故事详情、个人工作台
- 技术负责人审批/负载页面、用户管理、缺陷管理、冲刺管理
- AI 生成/拆分/INVEST 检查、WebSocket 实时刷新

仍属于计划项或仅部分实现：
- 看板卡片当前使用线性 AC 进度条，尚未实现环形进度条
- 看板目标列高亮、筛选/排序面板、键盘快捷键尚未提供完整 UI
- 故事详情当前支持 AC 状态更新与证据填写，未提供独立的“新增/编辑 AC”交互
- 无障碍能力已有零散 `aria` 与键盘处理，但未完成系统化焦点管理与审计

**核心价值**：
- 用户故事（User Story）为中心的需求管理
- 看板视图的拖拽式工作流
- AC（验收标准）驱动开发的可视化追踪
- 产品-开发-测试三角色协同

**技术栈**：
- React 19 + TypeScript
- Tailwind CSS 4
- Zustand（状态管理）
- @dnd-kit（拖拽）
- React Router v6
- 后端 API：开发环境 `http://localhost:8080/api`，生产默认同源 `/api`

## 🎯 设计理念

### 美学方向
**"Calm Workspace"（克制工作台）**

- **色调**：深海蓝 + 暖灰白 + 少量薄荷绿点缀
- **字体**：Playfair Display（标题）+ Inter（正文）
- **风格**：厚重、内敛、清晰分层，优先保证阅读节奏和空间呼吸感
- **动画**：仅保留必要的状态反馈，不使用抢戏的位移和漂浮感
- **导航原则**：顶部是应用壳层，左侧才是主导航，避免重复表达同一层信息

### 当前收口结论
1. **项目工作台**：项目列表、项目详情、缺陷管理、个人工作台已统一为实体卡片风格
2. **交互表达**：统一按钮、表单、状态面板，减少夸张 hover 和视觉噪音
3. **布局层级**：避免 sticky 元素遮挡内容，桌面端主导航与内容首屏保持对齐
4. **移动端策略**：优先保证单列节奏和点击区域，不为了并排布局牺牲留白

## 🚀 部署流程

1. **构建前端**
   ```bash
   cd storybook-page
   pnpm run build
   ```

2. **同步前端产物到后端 embed 目录**
   ```bash
   cd ..
   go run ./cmd/embedui
   ```

3. **构建后端单体程序**
   ```bash
   go build -o storybook-server ./cmd/server
   ```

4. **运行**
   ```bash
   ./storybook-server
   ```

5. **访问**
   - 默认地址：`http://localhost:8080`
   - 前端页面、`/api`、`/ws` 由同一进程提供
